# Reliability Test Matrix / 稳定性测试矩阵

> 目标不是证明“正常点一次能工作”，而是主动寻找状态竞争、重复操作、边界数据和资源释放问题。

## 1. 基础原则

- 桌面端和 Android 都要执行核心流程。
- 每项至少覆盖冷启动、热切换和失败恢复。
- 测试浅色、深色、暖色、冷色和自定义壁纸。
- 记录操作入口、队列来源、媒体类型、网络状态和最终界面，不只记录“卡了”。

## 2. 播放与队列

- 从曲库、最近播放、收藏、歌单、排行和云端列表分别点击歌曲，确认队列来源立即切换。
- 快速连续点击 20 次上一首/下一首，最终声音、标题、封面、时长、MV/唱片视图和队列高亮必须一致。
- 在音频 → MV → 音频、MV → MV 间切换，检查黑屏、位置归零、错误能力标签和声音残留。
- 到达队列首尾时验证列表循环、单曲循环、顺序和随机模式。
- 播放中切页面、最小化、恢复、打开/关闭播放队列，不得重播或丢失状态。

## 3. 导入、配对与删除

组合覆盖：

- 只有 MP3；
- 只有 MP4/MV；
- 先导入音频再配对 MV；
- 先导入 MV 再关联音频；
- 删除 MV 后保留音频；
- 删除音频后保留独立 MV；
- 删除当前播放项；
- 删除队列首项、中间项和末项；
- 重复导入相同文件、同名不同文件、改名后的同一文件。

删除后检查曲库、收藏、最近播放、排行、歌单、云端副本和当前队列，不能留下无效引用。危险操作要区分“移出曲库”“删除云副本”和“删除本地文件”。

## 4. 云端与网络

- 在线、离线、请求中断、恢复网络四种状态分别测试。
- 快速重复点击云端歌曲，确保旧请求被取消或忽略，不出现无限下载、错误离线提示或闪退。
- 云端列表最后一首继续下一首，播放器必须按队列模式处理，不能进入空白全灰状态。
- 多次刷新、搜索、筛选、删除云副本后，滚动位置和菜单锚点保持正确。
- 云端失败不得冻结本地曲库或停止正在播放的本地歌曲。

## 5. 元数据识别

- 标签完整、标签缺失、文件名混乱、中文、繁体、英文、现场版、合集分集分别测试。
- 快速连续发起识别时，新提示替换旧提示，不排成长时间消息队列。
- AcoustID 未配置、服务限流、无匹配和低置信度都有清楚但不过度技术化的提示。
- 切换界面语言后，菜单、提示、空状态和识别结果呈现符合当前语言偏好。
- 批量应用前能预览差异，用户确认过的资料不被低置信度结果覆盖。

## 6. 界面与输入

- 调整窗口到窄屏、常规宽度、最大化和多种系统缩放比例。
- 侧栏只出现一根滚动条；播放器、云列表和长页面滚动条不与玻璃边缘重叠。
- 右键菜单从点击位置附近出现，并在四个窗口边缘自动翻转。
- 音量悬停条能从按钮移动到滑条，不意外关闭；单击只切换静音。
- Android 键盘弹出后，输入框和提交按钮仍可见可点。

## 7. 完成标准

一次测试通过不等于关闭问题。高风险修复至少需要：自动化检查、桌面真实窗口回归、相关 Android 回归，以及一轮连续操作压力测试。若问题依赖具体媒体文件，应保留最小复现样本或记录其格式、时长和标签特征。
