- 建立 Flutter Windows / Android 双端结构。

- 引入多套壁纸、主题色和用户自定义背景。

## 0.4 初期：桌面交互与 MV

- 音频和本地 MV 进入统一曲库与播放流程。

- 侧栏常用歌单支持折叠与筛选。

## 数据与统计

- 播放事件从简单累计次数扩展为可支持最近播放和周期排行的数据。
- 收藏、歌单、排行、队列和删除操作逐步统一到稳定 ID 与单一状态源。
- 云端资料库增加搜索、筛选、排序、按歌手分组和明确的云副本删除语义。

## 可靠性阶段

项目经历了多轮真实操作与高频压力测试，重点解决：

- 从不同页面播放时沿用旧队列；
- MV 与音频切换时黑屏、画面不更新或能力判断错误；
- 快速下一首导致声音与界面不同步；
- 重复点击云端歌曲造成并发请求、错误离线提示或崩溃；
- 删除当前歌曲后遗留队列和页面引用；
- 右键菜单位置、重复滚动条和窗口缩放适配。

这些问题促成了请求代次、取消/去重、单一播放状态、媒体能力按曲目判断和系统化回归矩阵。

## 智能元数据与文字封面

- 导入阶段优先读取媒体标签并清理文件名。
- 引入 MusicBrainz 候选查询。
- Windows 端加入可选 Chromaprint / AcoustID 声纹回退。
- 文字封面从单字符扩展为尽量保留完整语义的短标题，同时保持小尺寸可读性。
- 识别结果支持预览，避免低置信度数据直接覆盖曲库。

- 增加简体中文、繁體中文和 English 界面。
- 建立中英文宣传网站、响应式真实截图和 GitHub Pages 发布流程。
- README 采用英文优先、完整中文同页展示；公开文档保留架构、设计、测试和维护知识。

## 当前方向

公开预览阶段优先级是稳定性、媒体状态一致性、完整本地化和数据可恢复性。歌词、进一步的智能识别、跨设备同步和更多平台支持属于后续增强，不应牺牲离线播放主链路。
