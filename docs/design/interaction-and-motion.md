# Interaction and Motion Guidelines / 交互与动效规范

## 1. 视觉目标

Sona 的液态玻璃不是单纯提高透明度。每个表面应同时具备：主题色关联、可见边界、稳定对比度和轻微层次感。亮色主题不能把白色卡片变成突兀实心块，深色主题也不能用过重黑影把内容压暗。

- 内容卡片使用主题派生的玻璃底色、细描边和有限阴影。
- 当前选中态必须比普通状态更容易辨认，不能只依赖与主题色接近的填充色。
- 歌名、歌手、次数与类型标签维持清晰的信息层级。
- 自定义壁纸需要根据实际背景亮度调整前景对比，而不是只按预设主题名称判断。

## 2. 桌面键鼠规则

- 左键歌曲：播放，并以当前可见列表建立新队列。
- 右键歌曲：菜单从鼠标位置附近弹出，并自动避开窗口边缘。
- 高频菜单保持紧凑；危险操作与普通操作分组，删除必须写清影响范围。
- 播放队列从窗口侧边柔和展开，不遮断主内容，也不改变播放状态。
- 音量按钮单击切换静音；悬停显示竖向调节条，鼠标移入滑条后不能提前收起。

## 3. 播放控制排列

控制区应围绕播放/暂停保持视觉对称。上一首和下一首紧邻中心控制；循环、队列、收藏、音量等次级按钮分布在两侧，但不同页面使用同一相对顺序。切换歌曲时标题、封面、MV/唱片能力和队列高亮必须同时更新。

## 4. 响应式布局

- 设计覆盖小窗口、常规桌面窗口与全屏，而不是按单一分辨率截图实现。
- 使用可用宽高和断点决定列数、间距与卡片宽度。
- 图片使用等比缩放，不通过固定宽度把内容拦腰裁断。
- 标题允许合理省略，但主要数值、播放次数和关键操作不能被挤到不可见区域。
- 侧栏只保留一个滚动容器；头部和账户入口固定，中间导航独立滚动。

## 5. 键盘避让

登录、注册和编辑表单呼出手机键盘时，弹窗应柔和让出空间，内容可滚动，底部按钮始终可点。

| 项目 | 规范 |
| --- | --- |
| 键盘高度 | `MediaQuery.viewInsetsOf(context).bottom` |
| Material 对话框 | 优先使用 `AlertDialog` 自带避让，不重复叠加位移 |
| 自定义对话框 | 240 ms、`Curves.easeOutCubic` |
| 内容尺寸变化 | `AnimatedSize`，180–220 ms |
| 安全区域 | `SafeArea`，水平 20–24 dp，垂直约 24 dp |
| 超长内容 | 表单区域滚动，操作按钮保持可见 |

让位只移动容器，不缩放文字和按钮。不能同时使用系统对话框避让与额外键盘高度位移，否则会发生双重上移。

## 6. 动效节奏

- 播放、暂停、切歌、拖动进度必须立即响应。
- 收藏、音量、选中状态使用 100–160 ms 的轻反馈。
- 卡片和页面过渡通常使用 180–260 ms 的 `easeOutCubic`。
- 菜单只动画自身的 opacity / transform，不让整页背景重新模糊。
- 壁纸特效优先和谐与性能；没有合适特效时，宁可保持静态。

## 7. 性能边界

避免在高频交互中重复解码壁纸、重建大范围 `BackdropFilter`、销毁视频纹理或触发整页 `setState`。Windows 原生视频输出应保持稳定挂载，MV 与音频切换通过媒体状态协调，而不是反复重建视频表面。
