# Sona：键盘避让与柔和过渡动效规范

## 这次确认的体验目标

用户在登录、注册等表单中呼出键盘时，弹窗不是突然跳位，而是以柔和、明确的方式向上让出空间；内容可以滚动，底部操作按钮始终完整可点。动画服务于可用性，不用“缩小到挤在一起”换取动画感。

## 可复用的动效配方

| 项目 | 规范 |
| --- | --- |
| 键盘避让 | 读取 `MediaQuery.viewInsetsOf(context).bottom` |
| 位移动画 | 使用 Material `AlertDialog` 的原生键盘避让；不要在其外重复包一层基于键盘高度的位移。若后续改为自定义 `Dialog`，才显式设置 240 ms / `Curves.easeOutCubic` |
| 内容尺寸变化 | `AnimatedSize`，180–220 ms，`Curves.easeOutCubic` |
| 弹窗最大高度 | 始终小于可视窗口高度；超过时让表单内容滚动 |
| 操作按钮 | 固定在弹窗底部，不能和输入框重叠；小屏幕可换行但不能被遮挡 |
| 安全边距 | 使用 `SafeArea` / 水平 20–24 dp、垂直 24 dp 的边距 |

## Sona 已采用的位置

- 云账号登录与注册弹窗：键盘出现时采用 Material 原生避让；表单区域可滚动，取消与提交按钮保持可操作。

## 后续适合采用的位置

- 新建/编辑歌单弹窗
- 更换封面、添加 MV、背景裁切等需要输入或选择的底部面板
- 云端冲突确认、删除确认等较长内容的对话框

## 不应滥用的位置

- 播放/暂停、切歌、拖进度条：这些必须立即响应。
- 音量、收藏等高频操作：可以有 100–160 ms 的轻微状态反馈，但不要套长缓动。
- 列表滚动本身：优先保证跟手，不加额外“漂浮”动画。

## 实现原则

1. 先保证键盘出现后所有关键控件仍可见、可点。
2. 让位只移动容器，不缩放文字与按钮。
3. 由系统 `viewInsets` 驱动，适配 Android 各种键盘和屏幕尺寸。
4. 动画只表达布局变化；成功、失败必须另有明确中文反馈，不能用动画代替结果提示。

## 技术关键词

`Dialog.insetAnimationDuration`、`Dialog.insetAnimationCurve`、`MediaQuery.viewInsetsOf`、`AnimatedSize`、`SingleChildScrollView`、`SafeArea`、`easeOutCubic`。
